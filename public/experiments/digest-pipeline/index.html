Fully unattended

A private parent digest

My kids’ school sends a lot of email in a lot of formats. Every morning, Claude reads what’s new, keeps what parents need, and publishes it to a password-gated page with an RSS feed. No one reviews it before it goes up.

  1. A Windows scheduled task fires at 7:30am
  2. run.ps1 pipes PROMPT.md into claude -p, Claude Code with no human at the keyboard
  3. Claude searches Gmail for school mail since the last run, and opens the “click here to view” links to get the full text
  4. Classifies each email, drops billing and one-family notes, keeps children to first names
  5. Writes three JSON files: the items, the upcoming dates, and its own state
  6. git push, and Vercel redeploys the page
  • A watermark. The state file records the newest email it has handled and every thread it has seen, so a run never counts anything twice.
  • A kill switch. An empty file named PAUSED stops every run until it’s deleted.
  • “Prefer leaving an item out over guessing.” The prompt’s first paragraph, because there is no one to ask.
  • A log. Each run ends by printing what it saw, kept and dropped, with a reason for every drop.
  • Why it runs at home. The Gmail connection is signed in on my desktop. A cloud runner would need a stored token instead.
Before the digest

Beverly Civic Assistant, a chatbot

Ask a question about Beverly, get an answer with source links. Scrapers pulled the city calendar, news, Council, Planning Board and ZBA minutes, and budget PDFs. Everything went into a vector database (Pinecone, a search index that matches by meaning), and Claude Haiku wrote answers from the top matches. A GitHub Action re-scraped daily.

39/42questions where it found the right source, on a test set written with known answers
  • Write the test set early. Forty-two questions with known answers is a cheap way to know whether retrieval works, and to notice when a change breaks it.
  • Free tiers run out. Indexing paused when the monthly embedding quota ran out. The scrapers kept running, so the data stayed fresh.
  • A chatbot waits for a question. Most residents don’t know which question to ask. That gap is what a weekly digest fills.
  • The scrapers outlived it. The minutes scraper, OCR fallback included, is the piece most worth reusing. Code on GitHub.

Pointing this at housing across the North Shore

A public database of what councils, planning boards and zoning boards decide about affordable housing, town by town, on a map. Here is what already exists for each piece, and what would be new.

Council, Planning Board and ZBA minutes
Starting point Have itscrape_minutes.py already pulls Planning Board and ZBA minutes from Beverly’s Agenda Center, with OCR for scanned PDFs.
NoteAgenda Center is a CivicPlus product that many Massachusetts towns use. Same platform means the same scraper with a new web address and board IDs. Towns on anything else need their own adapter.
Only what touches housing
Starting point AdaptA classify step with written keep and exclude rules, the same shape as the parent digest’s.
NoteName the signals: Chapter 40B comprehensive permits, inclusionary zoning, MBTA Communities (Section 3A) zoning, ADUs, CPA and housing trust votes. Log every exclusion with a reason, so you can audit what it threw away.
A map you can click into
Starting point AdaptOne data file per town, each with a block that says where it came from, when, and how sure we are.
NoteThe map reads the files. Claude only ever edits the data, never the map. That split is what keeps the Beverly pages honest.
Board members and term dates
Starting point NewA hand-checked data file, not a scrape.
NoteTerms turn over and town pages lag. Put an “as of” date on every row and show it.
CPA, housing trusts, housing production plans
Starting point NewStatewide lists before town websites: the Community Preservation Coalition tracks CPA adoption, and the state housing office keeps approved production plans.
NoteOne trusted list beats thirty scrapers. Check these first.
Towns with patchy video
Starting point AdaptMinutes first, video where it exists.
NoteMinutes are slow, since a board approves them at its next meeting, but they are the official record. Video is fast and messy. The digest leans on video for speed and documents for accuracy.

What I’d pass on

  1. Spend your own time on judgment

    Claude does the listening, the scraping and the first draft. I keep the choosing and the editing. That split is the whole design.

  2. Write the rules down

    Voice, fidelity and attribution live in a CLAUDE.md file Claude reads every session. When I catch a mistake, the fix is a new line there, so the next draft doesn’t repeat it.

  3. If you can’t link it, cut it

    Every claim points to a moment in a recording or a page in a document. Readers can check me, and so can I.

  4. Transcripts are leads, not sources

    Automatic captions mangle names and numbers. Anything that matters gets checked against a posted document.

  5. Label how sure you are

    Confirmed from a primary source, modeled on stated assumptions, or illustrative. In the unattended pipeline, “partial” when a source wouldn’t open.

  6. Review where readers will read

    The draft goes up at an unlisted address as the real page, same layout, same links. I edit what readers will see, not a document that becomes it later.

  7. Let a script check the mechanics

    A timestamp that lands on the wrong second still looks perfect. Checking every link by hand on a Monday morning is not a plan.

  8. Unattended runs need brakes

    A watermark, a kill switch, a log of what it dropped and why, and an instruction to leave things out rather than guess.

  9. Ask Claude how to use Claude

    When you’re stuck on how to set something up, the first question goes to Claude. You’re already doing it. It’s the most useful habit there is with these tools.

A starter kit

What I could put together so your own Claude Code starts with the decisions I’ve already made, instead of rediscovering them.

  • A CLAUDE.md to start fromVoice, fidelity and attribution rules, rewritten for housing decisions across several towns.
  • The Agenda Center scraperMinutes and agendas by board and year, with the OCR fallback for scanned PDFs.
  • The promptsClassify (keep or drop, with reasons), summarize (neutral, sourced, no guessing), and the reuse prompt the digest already publishes.
  • A checkerA script that opens every source link and confirms it lands where the sentence says.
  • An orientation promptThe first thing to paste into Claude Code, so it interviews you before it writes any code. A draft is on the right.
orientation prompt · draft
I'm building a public database of decisions by North Shore city councils, planning boards and zoning boards of appeals that affect affordable housing. Before writing any code, read this whole message, then interview me.

How I want to work:
- Split the pipeline into steps that each write a file: find meetings, fetch documents, extract text, classify, summarize, publish. Each step can be re-run on its own.
- Every fact stays traceable. Each record stores its source URL, the page or recording timestamp, the date retrieved, and a confidence level (confirmed or partial).
- Prefer leaving a record out over guessing. Never invent dates, votes, names or numbers.
- Keep the rules in a CLAUDE.md at the repo root. When I correct you, propose a new line for that file.
- Explain what you're doing in plain language. I'm not a developer.

Start by:
1. Asking me which towns, which boards, and who the readers are.
2. Checking which of those towns post agendas and minutes on CivicPlus Agenda Center, which post meeting video, and which do neither.
3. Proposing a folder layout and a data format for one town, before scraping anything.
4. Building the whole pipeline for one town and one board, then stopping to show me the output.

What I’d like to hear about

  • What does your scraper produce today?And where does it run: your laptop, a server, a scheduled job?
  • Who is the reader?Advocates, residents, town staff, councilors. Each wants a different level of detail.
  • How fresh does it need to be?Weekly is forgiving. As-it-happens means fully unattended.
  • How will you check a summary before it’s public?The answer decides how much of the pipeline needs a person in it.
  • Which towns first?One town, one board, end to end, beats ten towns halfway.
